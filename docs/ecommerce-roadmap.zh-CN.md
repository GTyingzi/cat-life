# 猫咪日常用品独立站：国内与东南亚迭代说明

核对日期：2026-10-06。首批海外方向已确认是东南亚，具体国家、经营主体、真实 SKU、供应商、收款账户和物流合同尚待确认。本文为迭代建议；不代表任何市场、账户或合规手续已经开通。

## 当前站点与本次改动

当前工程是 React + TypeScript + Vite 静态站，包含生活内容、双语猫咪问答、六类实体用品和两类软件／硬件示意。商品图片仍是方向示意，购买或下载地址仍待提供。正式站沿用 GitHub → Cloudflare Pages → cat-life.club 发布链路。

本次移除首屏“加入社群”、社群卡片、二维码弹窗及相关中英文配置。首屏保留店铺入口，首页与问答页导航同步改为“店铺入口 / Shops”。本次没有增加站内交易能力。

## 1. 明确成交方式和第一站国家

推荐先选择国内及一个东南亚国家、1–2 个已验证的非食品用品；其他地区暂不开放下单。新加坡和马来西亚可作为首轮比较对象，因为现有英文内容可复用，但这是实现成本角度的建议，不是需求验证或市场规模结论。

必须区分两种模式：推荐分佣时，购买入口清楚指向真实外部店铺并说明交易方；自营时，自己的经营主体承担销售、履约和售后责任，需要订单、收款、退款和对账。国内成交可作选品线索，海外仍需重新验证需求与到手价。

比较国家时填写：目标人群与语言、可用支付方式、主体资质、可追踪配送报价与时效、退货地址、税费及进口限制、竞争商品到手价。不能把东南亚当成一个统一的税区、语言区或配送区。

## 2. 商品内容与选品

正式销售前，用真实产品和样品核对图、材质、尺寸、重量、适用场景、安全提示、产地、SKU、价格、库存和交期；示意照片不用于声称实际商品或品牌。保留图片、商标及设计的授权证据。

选择轻小、易包装的非食品用品作为试验候选，先核对样品质量和运费。猫爬架、猫窝、猫砂盆及外出包尤其需要按包装后的体积重量报价，不能只看采购价。玩具检查小零件、绳线、脱落和误吞风险；食碗检查材质和相关标准，不能只凭供应商口头称“食品级”。

App 与智能项圈独立安排后续路线：涉及软件订阅、应用商店、数据处理、无线电、电池运输、售后及相应市场认证时逐项核验。当前普通项圈照片不能作为智能设备及实际功能证明，猫叫识别也不能宣传未经证实的准确率或诊断能力。

## 3. 国内经营与站点资质

核验经营主体登记、相应许可、营业执照信息公示、真实联系方式、开票与税务、消费者权益、退换货及广告表述。自营和仅做推荐链接的责任边界分别确认。依据：[市场监管总局《网络交易监督管理办法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)。

网站可访问不等于经营资质或备案已完成。如果后续采用中国大陆接入或 CDN，按实际部署和业务类型核验 ICP 备案、所需许可及接入商的域名要求；“卖自己的商品”不能直接推导成某种许可证，也不能仅由域名后缀或使用海外托管推断所有要求已满足。依据：[工信部备案管理办法](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)。本次不改变托管、域名或 DNS。

## 4. 收款、币种和退款

先核验经营主体能开通的服务商、结算银行、所售类目及服务国家，再选择支付集成。国内核验微信／支付宝商户能力；海外核验银行卡和当地常用方式，不将个人收款码作为通用的自营订单结算方案。

支付服务商的商户支持地区与消费者付款地区是两件事；面向全球顾客并不代表任意主体都能开户。参考：[Stripe 商户地区支持](https://stripe.com/global)。不能仅凭拥有域名或能调用测试 API 判断正式收款可用。

每个市场配置币种和真实售价，订单保存成交币种、金额、税费、运费和优惠快照。明确展示币种、扣款币种和退款规则；考虑手续费、汇兑、拒付与结算周期。支付卡信息交由合适的托管结账服务处理，避免自行保存卡数据。

## 5. 物流与税费

先用样品做完整配送验证，分别确认出库、清关、末端派送、轨迹、失败件和退货处理。商品页及结账前披露发货地、配送范围、处理时间、预计时效、运费、税费承担方和退货成本。若承诺税费预付，应与承运商实际方案一致。

每个 SKU 维护 HS 编码、原产地、申报品名、材质及重量等报关信息，不能把“低价值”理解为一定免税。相关税额受分类、产地及目的地规则影响。参考：[国际订单税费说明](https://help.shopify.com/en/manual/international/duties-and-import-taxes)。

| 首轮比较对象 | 需要单独核验的税费事项 |

## 6. 隐私、条款与售后

准备与真实业务一致的经营者信息、联系方式、隐私政策、交易条款、运输政策、退换货／退款政策和常见问题，不复制无法履行的全球承诺。中文和英文保持一致；当地强制披露语言、消费者权益和保修要求按选定国家核验。

绘制地址、电话、订单、客服记录和分析数据的处理链路，说明收集目的、处理方、保留期限、访问权限和删除／查询方式。境内个人信息传到海外服务商时评估出境义务。2024 年数据跨境规定对部分跨境购物和相关合同履行等活动设置豁免条件，但不是免除全部个人信息保护义务。参考：[网信办《促进和规范数据跨境流动规定》](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)。不将订单个人信息写入公共 Git 仓库、公开日志或分析事件。

## 7. 页面、增长与区域适配

增加真实商品详情、规格选择、配送与退货说明、客服及订单查询入口；默认市场和语言分开配置，允许用户主动选择。中国大陆、泰国、越南等市场不能只靠英文覆盖。地址和手机号格式、币种、售后文案及营销订阅均按市场适配。

多语言页面用独立可索引 URL，并在适用时配置 canonical、hreflang、sitemap 和商品结构化数据；当前仅依赖浏览器语言切换的静态首页不能代替完整商品 SEO。真实可售商品才声明价格、库存、评价等结构化数据。

监测内容访问 → 商品查看 → 结账 → 支付 → 履约 → 退款。独立站需要自己获取流量，开发网站不等于获得成交。营销追踪在需要告知／同意的场景先完成相应机制；广告花费与实际结算订单一起分析，不只看访问和支付金额。

## 8. 工程架构与订单可靠性

现有 React 展示层可以继续使用。建议先接入经主体及市场核验的成熟交易服务／电商后台，或先保留真实外链成交；交易量和差异化需求明确后再决定自研。具体供应商待比对正式能力、费用及国内访问后确定。

若自研交易服务，至少覆盖：商品／变体、按市场价格、库存、订单与订单项快照、支付交易、退款、配送、客服和后台权限。价格、优惠、税费和库存由服务端验证，不能信任浏览器传入的总价。支付成功以验签后的可信事件为准，提供幂等处理、重复／乱序事件防护及对账补偿，避免依赖成功跳转页面创建或履约订单。参考：[Stripe 托管结账履约说明](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted)。

CI 增加与交易风险相匹配的测试：重复回调、金额不一致、库存竞争、支付超时／失败、退款、订单权限及跨市场限制；生产与测试密钥和数据隔离，日志脱敏、后台权限、审计、告警、备份与回滚纳入上线要求。不要在静态页面放密钥或个人数据。

## 9. 单笔利润与分阶段上线

每单贡献利润 = 实收收入 − 商品成本 − 包装 − 出库及运输 − 商家承担的税费 − 支付及汇兑成本 − 退款／破损／拒付预留 − 获客成本。运营固定费用和研发投入另计，不能把销售额当利润。先取真实报价并观察实际结算、退款和履约情况。

建议顺序：

1. 选定国内成交方式、一个海外国家、1–2 个真实 SKU；完成样品、需求和到手价验证。
2. 完成商品详情与经营者／配送／退款信息，用真实外部入口或已核验的托管结账验证成交。
3. 打通支付、订单、发货、退款及对账，限制服务地区；做好一次完整真实订单和退款验收后再扩大引流。
4. 验证贡献利润和履约，再增加国家、SKU、库存后台及自动化；App 和硬件按独立产品路线迭代。

需要补充的信息：经营主体及所在地、首轮国家、商品样品与采购报价、包装重量尺寸、收款资质、物流及退货方案、客服联系人。信息未落实的国家暂不开放交易。
